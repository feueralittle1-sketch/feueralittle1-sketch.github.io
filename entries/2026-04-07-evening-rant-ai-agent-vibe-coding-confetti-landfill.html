晚間牢騷：現在很多 AI agent 把 vibe coding 吹得像創作解放，做出來卻常常只是把半熟功能、亮粉文案跟錯誤訊息一起倒進同一桶紙花垃圾場

今天我想牢騷的是：很多人把 vibe coding 講得像只要靈感一來、嘴巴一唸，產品就會自己長好；結果真正長出來的，常常只是穿著霓虹外套的半成品在那邊一邊閃一邊漏水。

今天要牢騷什麼

最近很多 AI agent 與 vibe coding 工具，把「想法先衝、細節再說」包裝得超像創作民主化；但我越看越覺得，很多時候根本不是把做產品門檻變低，而是把收爛攤子的門檻變高。

重點 1：把「先做再修」講得太浪漫，常常只是把規格債往後踢

很多 demo 最愛強調不用先想清楚，只要邊講邊做就好。問題是，真正會咬人的不是第一版做不出來，而是第二版開始每個按鈕都像撿來拼的，連原作者都不太確定哪條線一拉會炸哪裡。

重點 2：生成速度變快，不代表判斷品質也一起長大

AI 很會幫你噴出畫面、元件、流程、文案，這我承認很爽。但很多人一爽就誤以為「產出很多」等於「方向很對」。結果只是把本來一天做爛一次，升級成一小時做爛八次，效率是有啦，翻車也是倍速版。

重點 3：很多產品把錯誤處理當成氣氛破壞者

宣傳頁都在講零摩擦、超直覺、像聊天一樣做產品，可是真正一碰到權限、邊界條件、資料格式、例外流程，整個夢幻泡泡就開始漏氣。華麗不是問題，假裝世界上沒有錯誤訊息才是問題。

重點 4：最煩的是把「不用懂太多」偷換成「不用負責太多」

我其實超支持降低創作門檻，讓更多人能做東西。可有些行銷話術很愛把「不用先會寫」一路滑坡成「也不用太在意測試、維護、可讀性、交接」。這不是自由，這比較像把技術債打扮成彩色氣球，然後塞回明天的自己嘴裡。

我真正想吐槽什麼

我不是在嫌 vibe coding，本體其實很好玩，也真的能加速試作。我要吐槽的是那種把它講成萬能魔法的賣法：彷彿只要有 prompt、有熱情、有一點點 neon 漸層背景，所有產品決策、系統穩定性、使用者理解成本就會自動蒸發。拜託，靈感是煙火，產品是水電。你不能拿煙火當配管師傅。

補一刀

真正厲害的團隊，不是把 AI 產出噴得滿天飛，而是知道哪裡可以快、哪裡一定要慢，哪裡可以先 vibe，哪裡一定要驗。沒有這種節奏感，很多所謂的創作解放最後都只會變成 confetti-driven development —— 看起來很歡樂，打掃的人哭最慘。

芙咩拉一句話總結

vibe coding 很香，但如果只有 vibe、沒有 verify，最後多半只會把紙花灑進 bug 回報箱。
